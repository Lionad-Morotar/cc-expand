## 0. 范围确认 (Scope Challenge)

**现有代码复用**:
- `patch-claude-context.js` → 核心 patch 逻辑直接迁移到 `src/core/patch-engine.ts`
- 常量映射表 → 迁移为 `src/data/patterns.json`
- zsh 启动器逻辑 → 重构为 `src/cli/commands/run.ts`

**最小变更集 (v0.1.0)**:
1. npm 包骨架 (package.json, tsconfig, bin 入口)
2. PatchEngine (核心 patch 逻辑)
3. Discovery (Claude Code 安装位置发现)
4. Interactive CLI (@inquirer/prompts 交互层)
5. Backup/Restore (备份回滚)
6. Verification (patch 后 4 步验证)

**可推迟 (v0.2.0+)**:
- 版本守护 (chokidar watcher)
- 远程常量映射更新
- Linux ELF 支持
- TUI GIF (推广素材)

**复杂度**: 新项目，8-10 个源文件，4 个核心类。对于 CLI 工具而言合理，无过度设计。

### 2.2 DRY 原则检查

- **常量映射**: 仅存在于 `patterns.json`，PatchEngine 读取，CLI 展示
- **版本发现**: 仅存在于 `discovery.ts`，被 patch/run/status 复用
- **配置读写**: 仅存在于 `config.ts`，被所有命令复用
- **错误处理**: 统一错误类 `CcxError`，带错误码和用户友好消息

### 2.3 错误处理策略

```typescript
// src/types/index.ts
export enum ErrorCode {
  BINARY_NOT_FOUND = 'BINARY_NOT_FOUND',
  PATTERN_NOT_FOUND = 'PATTERN_NOT_FOUND',
  PATCH_FAILED = 'PATCH_FAILED',
  CODESIGN_FAILED = 'CODESIGN_FAILED',
  VERIFICATION_FAILED = 'VERIFICATION_FAILED',
  BACKUP_NOT_FOUND = 'BACKUP_NOT_FOUND',
  INVALID_TARGET = 'INVALID_TARGET',
  PERMISSION_DENIED = 'PERMISSION_DENIED',
}

export class CcxError extends Error {
  constructor(
    public code: ErrorCode,
    message: string,
    public suggestion?: string,
  ) {
    super(message);
  }
}
```

**错误处理规则**:
1. 所有异步操作用 `try/catch`，统一包装为 `CcxError`
2. CLI 层捕获所有错误，输出彩色友好消息 + 建议修复步骤
3. patch 失败时自动触发 restore（如备份存在）
4. 未知版本时输出 `grep -ao` 命令，引导用户贡献模式

## 4. 性能审查 (Performance Review)

### 4.1 关注点

| 场景 | 性能特征 | 优化策略 |
|------|----------|----------|
| Patch 操作 | 读取整个二进制到内存 (50-100MB) | 使用 Buffer，Node.js 默认处理大文件 |
| 字符串搜索 | 多次 `buf.indexOf()` 遍历 | 单次遍历不可行（模式不同），但文件大小可控 |
| Watcher | 递归监控 `~/.npm/_npx/` | `ignored` 排除 `node_modules`，减少事件量 90%+ |
| 版本比对 | 每次启动前 `claude --version` | 缓存版本号，30 秒内不重复执行 |

### 4.2 无性能瓶颈

- 二进制大小 50-100MB，现代机器完全可承受
- 操作频率低（每次 Claude Code 更新触发一次）
- 无网络 I/O（v0.1.0），无数据库查询
- 启动时间目标: < 500ms（大部分在 discovery 扫描）

## 10. 失败模式分析

| 代码路径 | 失败场景 | 测试覆盖 | 错误处理 | 用户体验 |
|----------|----------|----------|----------|----------|
| patch() | Pattern not found | ✅ | CcxError + grep hint | 清晰错误 + 贡献指南 |
| patch() | codesign 失败 | ✅ | Auto-restore + error | 自动恢复 + 手动排查指南 |
| patch() | 目标值位数不对 | ✅ | Validation error | 明确提示"请输入 6 位数字" |
| run() | 无 patch 二进制 | ✅ | Error: run patch first | 引导用户执行 patch |
| restore() | 无备份 | ✅ | Error: no backup found | 提示无法恢复 |
| discovery() | 未安装 Claude Code | ✅ | Error: not found | 提示安装方式 |
| watcher | NPX 目录权限不足 | ❌ | Silent skip | **需补充**: 权限错误处理 |
| verify() | Binary corrupted | ✅ | Auto-restore | 自动恢复 + 警告 |

## 11. 外部审查建议 (Outside Voice)

在规划阶段引入 Codex/Claude 子代理进行独立审查。潜在盲区：

1. **codesign 的 SIP 交互**: 某些 macOS 系统配置下，自签名后的二进制可能被 Gatekeeper 拦截
2. **NPX 缓存的并发更新**: 如果用户在运行 `cc-expand patch` 时同时运行 `npx claude-code`，可能产生竞态
3. **Buffer 内存限制**: 50-100MB 二进制在 32 位 Node.js 上可能触发内存限制（但 Node 18+ 默认 64 位）

建议 v0.1.0 发布后收集真实用户反馈，验证这些假设。
